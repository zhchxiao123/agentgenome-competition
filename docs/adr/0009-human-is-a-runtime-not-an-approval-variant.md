# human 是运行时,不是审批的变体

"人参与"这件事在系统里已经存在了几处:结对会话、人工审批、基因组任务的模块边界确认、质询
回注意见。每处都是特设实现,四种记录形状,而**没有一种能回答"把这个 Job 直接交给人做"**
这个最朴素的需求。

要补上它,有两个位置可选:长在审批面上(它已经有"等人"的机制),或者长成一个新的运行时。

## 决定

**human 是一个注册运行时**,与 claude-code / qwen-code / agentteams 并列。派给它的 Job 不拉
子进程,而是投进某人的 Web 待办;人干完活,产物按同一份 `result.json` 契约交付,过同一套
schema 校验,失败同样打回。

判据是**这两件事回答的问题不同**:

- 审批回答"这个产出可不可以"——裁决,带否决权,直接驱动状态迁移,面向整个任务;
- human Job 回答"这份活谁来干"——执行,状态内部的一次作业。

把执行塞进审批体系,审批面会长出上传产物、契约校验、产物槽这些它不该有的器官;反过来把裁决
塞进 Job,人工审批的否决权会变成一个 Job 的返回值。

由此推出的三件事:

1. **挂起不是失败。** `run_job` 投完待办立刻返回一个挂起的结果——不复用失败语义,否则状态机
   会重试、升级、扣一轮修复轮次,而这三样对"人还没开始干"都是错的。
2. **"继续"就是崩溃恢复。** 人交完活,产物写进这次派发**当初分配的那个产物槽**;照常推一步,
   处理器的幂等约定会认出它并抛出本来就该抛的事件。整条恢复路不需要任何内存态。
3. **三态是组合,不是三种原语。** `auto` / `manual`(节点指定 human)/ `assisted`(自动节点 +
   人的确认节点)。assisted 因此自动获得待办、超时三段、改派、RBAC 全套设施。

## 代价

**系统里有两条"人参与"的通路,人得知道自己现在在哪一条上。** 审批看的是整个任务的 diff 并且
可以否决;待办看的是一份活并且要交产物。界面上必须分开呈现——混在一个列表里的话,"轮到你干活"
与"轮到你拍板"会长得一样,而它们需要的注意力完全不同。

**"与硅基无差别"这句话要靠一条纪律维持**:全代码库不许出现"因为执行者是人所以放宽"的分支。
它没有类型系统兜底,只有 grep 与评审——但它是这条设计的全部价值所在:一旦人这条路可以少交
一份产物、少过一道校验,自动化率这个指标就不再可比,而信任爬坡也就没法度量了。

**人的越权检查只剩一道。** 工具集那一层对人根本不存在(他手里是一台电脑),所以最小权限在
这条路上只靠 Job 结束后对着真实 git 工作树的那次核对。它因此不能被跳过——而与硅基有意不同
的是:越权时**拒收提交但不回滚工作树**,因为回滚对机器免费、对人是刚花掉的半天,而拒收已经
拦住了"越权改动进合并"这件真正要拦的事。
