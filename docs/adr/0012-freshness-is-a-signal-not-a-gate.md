# 保鲜靠信号,不靠门禁

知识树只会生长,不会察觉过期:卡片自带 `scope`,任务自带变更清单,两者天天在路由里
相遇("取知识"),却从没反向用来质疑知识("代码改了,卡片跟上了吗")。hits 记账说得出
哪张卡有用,说不出哪张卡在撒谎。

## 决定

任务终结时,用变更清单反查卡片 scope,把怀疑记进**可疑账**(`tasks/card-suspects.json`,
运行态账本,与 hits 的曝光账/待记账并列第三本):

- **可疑过期**:变更命中某卡覆盖范围而本轮没有对应的知识更新(变更清单里不含卡片
  文件本身)。只看成功的任务——失败/取消的改动没有合入,知识没有理由跟着一份不存在
  的变更走。
- **教训蒸发**:fix 类任务(修复轮次 > 0 且 COMPLETED)蒸馏后没有产出任何经验卡片。

三条硬约束:

1. **软信号,不是门禁。** 账非空不阻塞任何状态迁移、不阻塞提交——状态机与提交管线
   根本不 import 这本账。硬门禁会逼出敷衍的卡片编辑:为了让任务过关而随手改两个字的
   "更新",是另一种腐烂,而且比薄卡更难发现。
2. **编排器只记账,不写知识树。** 与 hits 同一条约束(ADR-0005 的前提):落卡由知识
   写入路径(staging → 原子应用)做。
3. **响应二选一,都算清账。** 知识更新工序消费时,"改卡"与"核对过,无需更新"都是
   合法响应;后者留痕(带核对的 task_id)。没有这个出口,保鲜就退化成硬门禁。

## 后果

- 终态收尾按 `(kind, task, card)` 去重——崩溃恢复会重放收尾,账面余额不能变成
  "被重放过几次"。
- 变更清单走开发自述(产物目录),不走 worktree diff:终态收尾跑在工作区清理之后。
- 未响应的记录持续累积,余额在 `agctl knowledge status` 里可见——"知识树健康吗"
  有了一个不靠自述的答案。
