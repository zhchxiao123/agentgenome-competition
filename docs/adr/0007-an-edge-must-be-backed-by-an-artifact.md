# 边必须由产物背书:执行拓扑里什么算一条依赖

执行拓扑层让一个状态内部可以跑一张图(`core/topology.py`)。图一旦由 plan 阶段的 LLM
产出,第一个要回答的问题就是:**什么算一条边?**

最自然的答案是"先后顺序":拆图的人(或模型)脑子里有一条"先改契约再改调用方"的直觉,
于是画一条 A→B。但这条直觉在执行层是有害的——B 等 A 等的是**时间**,不是**东西**。
等待一个不给你任何产物的上游,收益为零,代价是把本可以并行的两件事串了起来。而且这类边
无法被机器判断对错:它只存在于写图那个人的脑子里。

## 决定

**edge (A→B) 合法当且仅当 `B.needs ∩ A.produces ≠ ∅`。**

1. **只有真实的产物流动构成边。** 这是「文件即协议」在图上的直接推论:员工之间不直接
   通信,只通过产物目录交换信息;那么"B 依赖 A"这句话的唯一可检验含义就是"B 要读 A 写
   的某份产物"。
2. **无背书的边**(假边)**在派发前被拒绝,不被静默剪掉。** 两种处理的后果完全不同:
   自动剪边会让事件面里记录的图与提交上来的图不是同一张,而"图实例可回放"是整层的地基
   之一——回放一张没人写过的图,比拒绝一张画错的图糟得多。
3. **`checker` 节点也产出。** 由 (1) 直接推出:`critique(checker) → refine` 这条边靠
   `critique.json` 背书,把检查节点定义成"只评估、不生产"的话,它的每一条出边都会被自家
   校验器判成假边。所以 work 与 checker 的区别不在有没有产出,而在**产出物的去处**:
   work 产出资产(进版本面),checker 产出判定(只进产物面与事件面,`write_scope` 必须
   为空)。

## 代价

**表达不了纯粹的时序约束。** "我就是想让 A 先跑完再跑 B,哪怕 B 不读 A 的任何东西"这件事
说不出来了。这是有意的:那种约束要么其实存在一份没被声明的产物(那就声明它),要么其实是
写集冲突(那由写集检验管),要么就是不必要的串行。

**报错要够具体才不算白拒。** 拒绝的第一读者是下一次拆图的 LLM,所以每条假边的报错都点名
到边与缺失的产物名(「节点 B 声明消费 spec.md,但上游 A 不产出它」),而不是"图不合法"。
