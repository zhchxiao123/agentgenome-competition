# 知识地图在磁盘上是一棵树,旧的单文件被拒收而不是兼容

项目地图原本是一个 `project-map.yaml`,装下项目信息、全部模块的运行信息、跨模块契约与数据
存储。两个模块的示例仓上它工作得很好。五十个模块的中台上它有两种失效方式,而两种都不是
"慢",是"错":膨胀成一份没人愿意打开、于是开始撒谎的两千行 YAML;或者被整份塞进每一个员工
的上下文包,把预算吃光、让真正相关的那几十行淹没在无关知识里。

改成三层树:**根索引**只留身份与指针,**契约索引**单独承载跨模块的事实,**模块地图**承载
「这个模块怎么跑」。

## 装配后的消费面刻意不变

项目地图这个类型有三十处消费方(上下文组装、集测判定、门禁配置、风险评级、图谱同步、REST
接口……)。分层只改**它从哪儿装配出来**,不改它装配出来长什么样——否则一次存储分层的改动会
波及全仓,而那和分层本身毫无关系。`assemble` 与 `write_tree` 是一对严格互逆的操作,`assemble
(write_tree(m)) == m` 是被测的硬约束。

## 旧文件拒收,不做双形态兼容

同一个路径可以同时接受两种形状——检测一下走两条分支就行。我们没有这么做:两种形状会一直
共存下去,而每一处新增的知识字段都要问一遍"这个放哪一边"。现在的行为是识别出旧形状后抛一个
指向 `agctl genome migrate` 的错误。

代价是存量 Workspace 必须跑一次迁移才能继续用。收益是**任何时刻树只有一种形状**。

选择拒收而不是静默兼容,还有一个具体理由:严格模式对旧文件的报错是「多了个 interfaces
字段」,读起来像拼写错误,不像"该迁移了"——而人会照着报错去删那个字段,把契约弄丢。

## Consequences

- 认知卡在模块地图里存的是 **Workspace 相对路径**,不是模块目录内的基名。存基名更整洁,但
  那要求装配时把目录拼回去,而拼回去的只能是约定的那一个目录——于是任何指到别处的认知卡在
  一次写回之后就指向了一个不存在的文件,静默地。往返必须逐字段相等,这一层才敢说"只改存储、
  不改语义"。
- 「认知怎么演进的」不再等于「`project-map.yaml` 的 git 历史」。版本与 diff 要覆盖整棵树
  (根索引 + 契约索引 + `modules/**`),否则界面上会安静地退化成"只有模块清单变过"。
- 迁移不创建任何功能点。旧地图里没有那一层,凭空捏造就是污染;那一层由知识初始化读代码后
  产出。见 [ADR-0003](0003-knowledge-map-is-complete-upfront-not-lazily-grown.md)。
