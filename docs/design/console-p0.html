这一版按评审改掉的六处

问题原稿的做法改成
模式做成 Tab 顶部「咨询 / 质询 / 结对」分段控件，可点切换；下方列表还有一个「模式」下拉，两个控件互相矛盾 模式是会话属性，显示为标题旁的静态标签，创建时确定后不可变。Tab 暗示可随时切换，而咨询只读、结对可写 —— 点一下就完成一次无闸门提权
画了不可能的状态 门禁显示「集成测试失败 6」，任务卡却是 REVIEWING 集测失败只会退回 DEVELOPING（附录 A #10）；REVIEWING 只能从 READY_TO_COMMIT 经 risk_high 进入。改成门禁全绿 + 命中 migrations → 高风险 → 审批中
⌘K 被占两次 顶栏搜索标 ⌘K，PRD 的全局对话抽屉也要 ⌘K ⌘K 留给搜索（已有），对话抽屉改 ⌘J。搜索框那句「或输入 / 快捷指令」本来就留了另一条路
上下文条层级错了 横跨整页压在三栏之上，看起来像页面属性；页面标题 + 模式 Tab + 上下文条三层 chrome 吃掉近半屏 移进对话栏内部 —— 它是这个会话的。省下的竖直空间还给消息流
上下文条与证据面板不分 两边列的都是卡片/文件/产物，看不出区别；门禁结果还在两处各画一遍，格式还不一样 上下文条 = 输入（带着什么在回答，可增删可钉住）；证据面板 = 输出（引用过什么，只读累积）。门禁只在消息流里出现一次
缺两个 PRD 必需件 没有有用/没用反馈；没有任何预算与超时提示 反馈补上并标明它记 hits（§10.2 的输入源）；输入框下常驻预算条与「空闲 30 分钟自动挂起」，会话列表里的挂起态也写明原因

词汇表对齐

员工统一为「架构员工 / 开发员工 / 集测员工」—— 原稿里「代码评审Bot」「DevBot」「性能Bot」三套命名混排， 而 Bot 不在词汇表里，代码评审与性能员工也不存在。

会话状态用进行中 / 已挂起 / 已结束。原稿的「已归档」被 CONTEXT.md 的 「已了结」词条明确列为 Avoid，且 PRD 27 里没有归档这一档。

任务 id 一律 ag-YYYYMMDD-NNN（见 core/task_ids.py）， 不是 TASK-2024-0501。

还没解决的一处

长会话的密度。这一屏只画了两轮。真正难的布局是 30 轮以上时怎么保持可扫读 —— 消息要不要折叠、工具步骤要不要默认收起、虚拟滚动的锚点放哪。这里只用「载入更早的 18 条」占了个位， 不算答案。建议实现前先拿真实会话长度试一版。
