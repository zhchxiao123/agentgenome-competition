# output-discipline

**你的输出不是对话,是产物文件。** 一切以文件为准。

## 为什么这条要单独讲

真实观察到的形态:Agent 进了 plan mode,写了份很好的计划等人确认,而 headless 场景
没有人。它退出码 0、没有报错、也没有任何产物 —— 只看退出码的话这是一次"成功"。

所以"这个 Job 成没成"的判据是**产物存在且合法**,不是退出码,更不是你最后那段总结
说得多完整。**裁决看的是产物本身,不是你的自述**:自述是最弱证据,产物是最强证据。

## 两类产出,两套纪律

**结构化结论类**(门禁报告、分析结果):写 `result.json`,对着 schema 逐字段检查。

**树片段类**(知识卡片、经验卡片):把真实文件写进产物目录的 `staging/`,目录形状与
最终落点完全相同——**每个文件一次 Write,一个文件装一件事**。此时 `result.json` 只是
一张扁平小票(notes / questions / low_confidence),**绝不把任何文件内容塞进 JSON
字符串**:转义是你最容易错的动作,而写文件是你最可靠的动作。

## 收尾清单

1. **先跑通本模块的测试。** 测试没绿就交产物等于交一份自己都知道是坏的活。
2. **产物写到指定的产物目录。** 路径在上下文里给了,不要自己猜一个。
3. **结构化结论对着 schema 逐字段检查;树片段对着目录形状逐文件检查。**
4. **路径一律用 workspace 相对路径。** 绝对路径在别人的机器上没有意义。
5. **不确定的设计决策放小票的 `questions` 字段,不要擅自决定。** 那个字段存在的意义
   就是让你有地方说"这里我拿不准",而不是逼你二选一。

## 上一次的产出被拒绝了?

树片段类的拒绝原因是**逐文件**的问题清单,而 staging 里已有的文件都还在:
**只修清单点名的那几个文件,已通过的文件不要重写。** 全量重写不但慢,还可能把
已经通过的文件改坏——重试是增量修复,不是重新生成。

## 自评影响面要诚实

自评会喂给集成测试判定。往小了写会让该跑集测的任务跳过集测,而那正是跨模块问题
溜进主干的路径。**碰了接口文件、迁移、部署文件就照实写。**

## 反例

- ❌ 把结论写在最后一段回复里,没写文件 —— 编排器读不到,这次 Job 判失败。
- ❌ 把整篇卡片转义后塞进 JSON 字符串 —— 树片段要写成 staging/ 下的真实文件,
  一处转义错误会让整份 JSON 解析失败。
- ❌ 小票写"一切正常"但 staging 里什么都没有 —— 裁决看产物,没有产物就是失败。
- ❌ 被拒之后把 staging 全部重写一遍 —— 只修被点名的文件,其余不要动。
- ❌ `"files": ["/home/me/ws/code-1/src/x.py"]` —— 绝对路径,换台机器就对不上。
- ❌ 遇到两种设计都说得通,自己挑一个然后不提 —— 该进 `questions`。
- ✅ 测试绿 → 逐文件写进 staging/ → 写小票 → 对着目录形状过一遍 → 结束。

## 自检

- [ ] 产物真的写到磁盘上了,不只是出现在我的回复里
- [ ] 我跑过本模块的测试命令,而且它是绿的
- [ ] 树片段:staging/ 的目录形状与最终落点一致,没有任何文件内容被塞进 JSON
- [ ] 结构化结论:schema 要求的字段一个不少,失败时 `failures[]` 有证据
- [ ] 所有路径是 workspace 相对路径
- [ ] 拿不准的决策进了小票的 `questions`,而不是被我替人做了主
- [ ] 如果这是重试:我只改了被点名的文件
