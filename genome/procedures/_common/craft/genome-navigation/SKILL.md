# genome-navigation

在基因组里按需取知识,而不是把整棵树读一遍。上下文包给的是**目录 + 已命中内容**,
剩下的要你自己去取。

## 为什么不能全量读

知识地图是一棵与代码结构同构的索引树,不是一个文件。一个 50 模块的项目,全量读完
会吃掉整个上下文预算,而其中 95% 与你手上这件事无关。被挤掉的恰恰是失败报告和需求原文。

## 步骤

1. **先看上下文包里已经给了什么。** 命中的功能卡片已经在包里,不要再去 Read 一遍。
2. **看目录行判断还缺什么。** 未命中的卡片只给了 `id + summary` 一行。凭这行判断
   "这张卡片和我要改的东西有没有关系"。
3. **按路径反查,不要按关键词猜。** 你要改 `src/order/reserve/timeout.py`,就去
   `genome/knowledge/modules/order-service/map.yaml` 里找 `scope` 覆盖这条路径的 feature,
   然后只读那一张卡片。
4. **读到 ADR 的链接再决定要不要展开。** 卡片的 `links` 指向决策记录;只有当你打算
   推翻或绕过某个既有决策时才需要读它。
5. **读完就停。** 取到足够动手的信息就动手,不要"顺便把相邻模块也了解一下"。

## 反例

- ❌ 一上来 `Read genome/knowledge/` 下的所有 `.md` —— 预算炸了,而且你还没开始干活。
- ❌ 按需求描述里的词去 Grep 整个知识树 —— 词对不上但路径对得上的卡片会被漏掉。
- ❌ 看到 `confidence: low` 的卡片就当它不存在 —— 低置信度是提醒你核对,不是让你忽略。
  核对完了顺手把它改准是有价值的产出。
- ❌ 上下文包里已经有 reserve-flow 卡片,又 Read 一遍原文 —— 白花一次工具调用。
- ✅ 看 diff 涉及哪些路径 → 在模块 map 里定位对应 feature → 只读那一两张卡片 → 动手。
